# BenchSift agent guide

BenchSift is an evidence-first catalogue for finding and comparing AI models,
published in English and French. This guide holds the contracts every change
must keep. The source and `package.json` define current behavior: when they
disagree with this file, correct this file in the same change.

## Before you edit

- Run `git status -sb` first. Preserve unrelated work, including untracked
  files, and keep it out of your commits.
- Use Bun for installation, scripts, and tests (`bun install`, `bun run <script>`);
  never npm. `package.json` and `Dockerfile` pin the same Bun version: use it
  when checking the lockfile.
- Finish the requested change and its verification. Ask only when missing
  information materially changes the result or the action exceeds the request.
- A commit, push, pull request, deployment, production refresh, or mutation of
  an external service needs an explicit user request. Authorization given
  earlier in the conversation still counts.
- `.data/` is local runtime state. `src/routeTree.gen.ts` and `.output/` are
  generated by the build: never edit them by hand.

## Data integrity

- Show only sourced data. An unavailable metric is `null`: never a fabricated
  value, `Unknown`, or zero. Zero is a measurement unless its source says
  otherwise.
- Field ownership:
  - Artificial Analysis owns model identity, benchmarks, speed, latency, and its
    published prices.
  - OpenRouter adds capabilities, pricing detail, rankings, and models missing
    from Artificial Analysis.
  - Models.dev fills missing specifications and can add models; it supplies no
    benchmark, speed, or pricing field.
  - Hugging Face provides official repository metadata and evidence about open
    weights.
- Resolve duplicate models by field ownership: keep first-party identity and
  Artificial Analysis measurements, update OpenRouter-owned fields from the
  matching entry, fill remaining gaps, then remove the redundant row. Hiding it
  is not enough.
- Apply normalization and exclusions both during ingestion and when reading
  historical caches. Reuse `lib/provider-map.ts` for creator and provider
  identity, and `lib/openrouter-model-filter.ts` for routers, services, moving
  `*-latest` aliases, and `:free` endpoints. A host or a model family alone is
  not ownership evidence.
- A source that renames a metric or publishes a new version gets an alias or a
  new key next to the old one, so historical caches still read correctly. Never
  present one methodology's value under another's label.
- When external data looks wrong, inspect the source objects and the cache path
  before changing a parser.
- Keep the source-count and partial-build protections in `lib/api.ts`: an
  incomplete refresh must never replace a healthy catalogue.
- Validate and encode external slugs and ids before using them as keys, paths,
  or URLs. Idempotent upstream requests use bounded retries and timeouts
  (`lib/fetch-with-retry.ts`).

## Benchmark pages

A benchmark page reads one upstream page or artifact and never invents what
the source does not publish.

- Split the code: a client-safe `lib/<benchmark>-data.ts` with types, parser,
  ranking, and URL-search parsing; a `server-only` `lib/<benchmark>.ts` that
  fetches and caches; a server function in `lib/server-fns.ts`; the view in
  `components/<benchmark>/`; the route in `src/routes/benchmarks/`.
- Parse defensively: a row needs a valid slug, a name, and at least one real
  measurement. Skip the row otherwise; do not pad it.
- Reuse `components/benchmark-page.tsx` for the header, stat tiles, and
  methodology disclosure before writing new layout.
- Register the route everywhere it is listed: `components/nav-links.ts`,
  `src/routes/sitemap[.]xml.ts`, `components/webmcp-provider.tsx`,
  `lib/agent-discovery.ts`, `server/plugins/logging.ts`, and the `nav`, `seo`,
  and page blocks of `lib/i18n.tsx`.
- Source text published in English only is translated in a dedicated
  `lib/<benchmark>-fr.ts`, keyed by the source id; an untranslated id keeps its
  English source.
- Document the source, its version, and what is deliberately left out under
  "Sources" in `docs/operations.md`.
- Cover the parser with a focused `lib/<benchmark>-data.test.mjs`.

## Server and public boundaries

- Route loaders call server functions in `lib/server-fns.ts`. Node APIs,
  filesystem access, secrets, and upstream requests stay on the server.
- Keep the `@tanstack/react-start/server-only` guard on dedicated server
  modules. Client code may import their types, never their runtime values.
- Read server configuration from `process.env`. Public responses and logs must
  not expose keys, `CRON_SECRET`, cache paths, schema keys, or internal errors.
- Initial SSR and the first client render must have the same structure. Read
  browser globals after hydration, or inside effects and event handlers.
- `/api/cron/refresh` and `/api/cron/status` require
  `Authorization: Bearer <CRON_SECRET>`. `/health` is public liveness with a
  sanitized catalogue status: degraded data alone must not fail the HTTP check.

## Product behavior

- French and English stay in parity in `lib/i18n.tsx`. Every page has an
  address per language (`/models`, `/fr/models`); the browser language is
  suggested, never forced.
- Shareable state lives in the URL: filters, selection, comparison, and the
  chosen benchmark view. Omit default values from the URL.
- Normal mode shows a compact ranking and collapses reasoning variants;
  Advanced and detail views may expose the family. Filters, search, and
  provider selection must not renumber global ranks.
- Use `components/link.tsx` for internal links unless the Router API needs its
  own.
- Reuse the semantic tokens of `src/styles/globals.css`, `components/ui/`, and
  `cn()`. Follow [PRODUCT.md](PRODUCT.md) for the warm-neutral visual language,
  mobile usability, keyboard access, visible focus, and reduced motion.
- Shared behavior has one home: do not copy logic, markup, or styles from one
  page to another. No inline scripts or inline event handlers unless
  technically required.

## Verification

Run the checks that match the change, then repeat them only for new changes or
failures.

| Change | Checks |
| --- | --- |
| Documentation | Referenced commands and links, consistency with the source, `git diff --check` |
| Code or data | `bun run test`, `bun run typecheck`, `bun run build`, `git diff --check` |
| Parsing, matching, filtering, ranking, cache, normalization | The above, plus focused `lib/*.test.mjs` coverage of the changed rule |
| Routes or server behavior | The above, plus a smoke test of the affected HTTP/SSR path on the production build (`bun run build`, `bun run start`) |
| Responsive UI | Both themes and both languages at 390 px, tablet, and desktop widths; keyboard navigation, `scrollWidth`, and the bounds of critical elements |
| Dependencies or lockfile | `bun install --frozen-lockfile` with the Bun version used by Docker |

- A data-backed view is verified against a real cache or live source data. An
  empty shell is not evidence.
- A parser for an external page is checked against the current live payload,
  not only against a fixture.

## Handoff

Report what changed, what was verified, and what was not. Keep local checks
apart from GitHub, deployment, refresh, and public-production checks, and name
any failure you did not fix, with its cause when you know it.
